# MazeLab

面向数据结构与算法学习者的迷宫生成、求解与逐步可视化工具。

## 1. 项目背景与目标

**面向谁：** 正在学习栈、队列、优先队列、并查集和图遍历的学生/自学者；需要准备演示和练习题的教师/助教。

**解决什么问题：** 常见迷宫示例只给最终图案，不展示算法过程；随机结果难以复现；缺少自动验证，难以确认迷宫连通性、无环性、路径合法性、BFS 最短路性质。

**已完成功能：**

- [x] 迷宫核心数据结构（单元格、墙位掩码、JSON 导入导出、字符画渲染）
- [x] DFS 回溯生成（一键 + 逐步）
- [x] 随机 Prim 生成（一键 + 逐步）
- [x] Kruskal + 并查集生成（一键 + 逐步）
- [x] BFS 求解（一键 + 逐步）
- [x] A* 求解（一键 + 逐步）
- [x] 命令行工具 generate / solve / validate
- [x] 自动测试：连通性、无环性、路径合法性、seed 复现
- [ ] 本地 Web 可视化（未实现，见第 6 节）

## 2. 课程知识与核心设计

| 算法           | 数据结构              | 用途               |
| -------------- | --------------------- | ------------------ |
| DFS 回溯生成   | 栈                    | 生成路径较长的迷宫 |
| 随机 Prim 生成 | 优先队列 / frontier   | 分支更均匀         |
| Kruskal 生成   | 并查集                | 随机边合并         |
| BFS 求解       | 队列                  | 最短路             |
| A* 求解        | 优先队列 + 曼哈顿距离 | 启发式搜索         |

**核心表示：** 每个单元格用四面墙位掩码（N=1, E=2, S=4, W=8），打通相邻两格时同时清除双方对应墙。这条"墙必须成对出现"的不变式由 `Maze.carve()` 唯一维护，`core/validate.py` 会独立复查；一旦有人手工改墙改错，`validate` 立刻报"墙位对称"失败。

**逐步可视化：** 生成器和求解器都以 Python 生成器 yield `StepSnapshot`，每个快照包含当前动作、当前格、栈/队列/堆内容、已访问集合、候选集合、路径与 `extra` 补充信息。因为生成器是惰性的，取第一帧不需要先算完整个迷宫；调用方边取帧边渲染，`extra["carve"]` 记录本帧新打通的边，重放这些边就能复原任意时刻的迷宫，不必每帧存一份完整网格。

**复杂度：** 设格数 n = R×C、通道边数 m = n−1。

- 三种生成算法都是 O(n) 时间（每格入栈/入堆一次、每条边被考察常数次），O(n) 空间；
- BFS 为 O(n + m) = O(n)，每个格子至多入队一次；
- A* 最坏 O(n log n)（每条边一次堆操作），堆大小为 frontier 规模；
- 并查集带路径压缩与按大小合并，单次操作均摊接近 O(1)。

**为什么选这些方案：**

- 生成用三种算法而不是一种，是因为它们产出的迷宫**形态差别明显**：DFS 倾向长走廊、死路少；Prim 分支短而均匀；Kruskal 是全局随机选边。三者都基于"生成树"这一共同数学结构（n 格、n−1 条通道、连通且无环），所以能用同一套 `validate` 判据统一验证，对比起来才有意义。
- BFS 与 A* 都实现，是为了让"最短路"这个结论可以被交叉验证：两个算法独立跑，路径长度必须一致（见第 5 节测试），这比单测一个算法更难出错。
- 墙位掩码 + 整数而非邻接表，是因为网格迷宫每条边的两端天然相邻，用 4 个比特就能完整表示一格的连通关系，序列化成 JSON 也只需一个整数矩阵。

## 4. 功能展示

**生成：** `examples/maze_8x12.json`（DFS，seed=7）与 `examples/solution_8x12.json`（A* 求解结果）可直接打开查看。

**三种生成算法的形态差异**（12×12，5 个种子取平均，脚本实跑）：

| 算法    | 平均死路数 | 平均最短路径长度 | 观感                    |
| ------- | ---------- | ---------------- | ----------------------- |
| DFS     | 16.2       | 49.6             | 长走廊、绕远，死路很少  |
| Prim    | 43.8       | 28.8             | 短分支多、分布均匀      |
| Kruskal | 42.8       | 28.4             | 全局随机，整体接近 Prim |

（死路 = 只有一条通道的格子；最短路径由 BFS 从左上角到右下角求得。这组数据解释了为什么"要长路径的迷宫"选 DFS、"要均匀分支"选 Prim。）

这一对比中 DFS 死路更少的部分由 `tests/test_generators.py::test_dfs_has_fewer_dead_ends_than_prim` 断言（5 个种子取总数，避免单次偶然）。

**逐步快照：** 每个算法都可取到逐帧状态，例如：

```python
import random
from mazelab.generators import GENERATORS

for step in GENERATORS["kruskal"].generate_steps(4, 4, random.Random(1)):
    print(step.action, "分量数 =", step.extra.get("components"))
```

## 5. 测试与结果

`pytest` 共 115 个用例全部通过（0.5 秒内），覆盖：

| 测试文件                 | 覆盖内容                                                       |
| ------------------------ | -------------------------------------------------------------- |
| `test_maze.py`           | 墙位对称、打通幂等、越界与不相邻、连通性、序列化异常、1×1 边界 |
| `test_generators.py`     | 三种算法 × 6 种尺寸均为完美迷宫、seed 复现、快照重放一致       |
| `test_solvers.py`        | 路径合法、BFS 与 A* 路径等长、无解、起终点重合、越界           |
| `test_validate.py`       | 四类缺陷（漏边、缺口、断连、成环）都能被检出                   |
| `test_cli.py`            | generate→solve→validate 全链路、错误输入退出码                 |
| `test_disjoint_set.py`   | 并查集合并、路径压缩、分量计数                                 |

**关键结论（均为实跑结果，不是估计）：**

1. 三种生成算法在 1×1、1×6、6×1、2×2、3×7、8×8 六种尺寸下生成的迷宫全部通过四项自检，`passages == n - 1`。
2. 相同 seed 完全复现，不同 seed 结果不同（8×8 下 5 个种子产生了 5 种不同迷宫）。
3. BFS 与 A* 在 3 种生成算法 × 10×10 迷宫上路径长度完全一致。
4. **一个与直觉相反的结果：A* 在完美迷宫上并不比 BFS 扩展得少。** 实测 8×8 / 10×10 / 14×14 各 5 个种子，扩展格数比值 A*/BFS 在 0.72–1.02 之间，有 4 次还略多于 BFS。原因是迷宫走廊迫使绕行，曼哈顿距离作为下界太松，大量格子的 f 值并列，A* 只能按平局顺序推进整片等高区域；开阔网格上这一现象更极端（3×3 全网的开阔区域里 9 格 f 值全等于最短距离，A* 会把 9 格全部扩展）。这一点写进了 `tests/test_solvers.py`，因此文档里不会出现"A* 一定更快"的说法。

**边界与异常：** 1×1（无通道）、单行/单列、起终点重合、目标不可达、越界坐标、损坏 JSON、非整数墙值均有对应用例；`mazelab solve` 对无解迷宫返回退出码 2，`validate` 失败返回 1。

## 6. 局限与改进

- 当前仅支持完美迷宫生成，尚未支持带环路或障碍的非完美迷宫；
- 逐步快照每帧保存完整迷宫，大尺寸下内存与传输开销待优化（现在改用 `extra["carve"]` 记录增量，消费方重放即可，但快照本身仍会复制 visited/frontier 集合）；
- Web 可视化尚未实现，目前只有字符画与 JSON 输出；
- 尚无算法性能对比实验的自动化脚本（第 5 节的 A* 数据是手工脚本跑的）；
- A* 只用曼哈顿距离，在走廊型迷宫上剪枝效果有限，可尝试"死路剪除"预处理或更紧的启发式。
